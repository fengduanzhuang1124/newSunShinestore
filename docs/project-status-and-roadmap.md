# 项目现状与开发路线

更新日期：2026-09-17

## 当前主线

第一优先级已经确认为独立的 Sunshine Inventory Management System 外挂进销存系统。

当前完成到：

- `inventory-system/` pnpm workspace、NestJS API、Vue 3 工作台、Prisma 7 Schema 和 MySQL migrations；
- 员工登录、JWT、门店/仓库权限和管理员敏感操作保护；
- 扫码入库、到期日期、批次库存、手工出库、盘点、库存流水和撤销审计；
- 当天入库、总库存、临期预警和 CSV 导出；
- 手机局域网访问、蓝牙扫码枪键盘模式、无横向溢出的响应式界面；
- 手机锁屏或页面重载后的本机入库草稿恢复，按员工与门店隔离；
- Moni POS 登录、门店、分类、商品、订单与退款/取消状态的只读核对；
- 奶粉候选治理、外仓商品只统计不扣本地库存的业务规则；
- POS 有条码商品候选、中英文名称审核、本地商品主档与多条码映射；
- Level 4 价格读取并按 POS 商品映射同步到本地门店商品；
- POS 订单观察表和模拟库存扣减；正式自动扣减仍保持关闭。

下一阶段：

- 完成真实初始库存录入和门店持续试用；
- 增加新品定期同步、差异审核和异常提醒；
- 在库存准确的前提下启用 POS 销售自动出库；
- 开发管理数据大屏的库存周转、滞销、销售和资金占用指标；
- 配置固定域名、HTTPS、备份、恢复和生产部署，消除局域网 IP 变化影响；
- CRMEB 商城、H5/PC 网页和微信小程序统一调用库存中心 API。

当前环境：Node.js 24、pnpm 11、Docker Desktop 和 MySQL 8.4 本地开发环境可用；前端默认端口5174，库存 API 默认端口3100。

## 状态说明

- `已有基础`：代码中存在主要实现，但不代表已经通过完整测试。
- `部分完成`：页面或 API 已存在，仍有模拟数据、契约或业务缺口。
- `未开始`：未发现可验证实现。
- `延后`：核心交易闭环稳定后再安排。

## 分阶段路线

### 阶段 0：需求、设计和开发环境

- 确认门店、仓库、商品、条码、日期和员工流程；
- 完成01–06号文档；
- 安装 Node.js、Docker 和开发工具；
- 确认第一门店/仓库名称及剩余业务待定项。

### 阶段 1：外挂库存数据和 API

- 创建 NestJS、Vue 3 和 Prisma 项目；
- 建立多门店、多仓库、商品、多条码和到期日期；
- 建立库存流水、汇总、权限和审计；
- 建立 migration、事务和自动测试。

### 阶段 2：扫码库存 MVP

- 扫码查询和未知商品登记；
- 手工/Excel/扫码初始库存；
- 入库、手工出库、调拨和盘点；
- 临期提醒和日期查询；
- 门店电脑和平板试运行。

### 阶段 3：试运行和 v0.1.0

- 门店 Mini PC/局域网部署；
- 员工培训和 SOP；
- 备份、恢复和监控；
- 试运行修正并发布 v0.1.0。

### 阶段 4：统一管理和线上销售

- 统一商品、订单、促销和物流管理；
- 英文网页销售端和微信小程序复用统一 API；
- 微信人工订单录入。

### 阶段 5：外部整合与 AI

- POS CSV/API 和销售对账；
- 销售大屏；
- FAQ 数据治理和 AI 员工辅助客服；
- 成本、隐私和质量评估。
