## 9. 证明材料的组合使用方式

| 需要说明的问题 | 建议配套材料 |
| --- | --- |
| 为什么开发这个系统 | 业务需求、项目路线图 |
| 系统如何设计 | 技术设计、数据库设计、API 文档 |
| 每天或每阶段做了什么 | 开发日志、CHANGELOG、Git 提交 |
| 功能是否实际实现 | 源代码、migration、测试报告 |
| 页面是否实际运行 | 页面截图、前端代码、接口测试 |
| POS 是否安全接入 | POS 专项说明、脚本、订单观察表、零正式库存变更记录 |
| 奶粉业务如何验证 | 奶粉候选表、审核记录、Excel 报表和预览图 |
| 后续如何继续 | 路线图、未提交工作清单和下一阶段计划 |

单个文件只能说明开发过程的一部分。将“需求文档 + 开发日志 + 源代码 + migration + 测试报告 + 截图/报表 + Git 记录”按日期对应起来，证明力更完整。

## 10. 建议的正式存档步骤

1. 提交前扫描并排除 `.env`、密码、POS key、token 和顾客敏感信息；
2. 按库存 UI、POS 只读同步、模拟扣减、奶粉治理、测试和文档拆分清晰提交；
3. 将功能分支推送到 GitHub，并保留 Pull Request 的服务器时间；
4. 对稳定阶段打版本标签，并保存发布说明；
5. 定期导出必要的数据库结构、migration 状态和脱敏审计记录；
6. 截图和 Excel 报表保留生成日期、规则说明及对应代码版本；
7. 后续开发继续同步维护开发日志、测试报告和 CHANGELOG。

## 11. 结论

目前本地工作区已经形成较完整的开发过程材料链：有需求和技术设计作为开发起点，有代码与 migration 记录实现过程，有测试报告和运行脚本记录验证过程，有截图及 Excel 报表展示阶段结果，也有 Git 提交固定已存档阶段。
