# 历史库存核对允许负数

## 目的

导入历史基准库存并补扣其后的 POS 销售时，部分条码可能没有基准库存，或销售数量大于已录入数量。系统保留负数作为待审核差异，不再把结果静默截断为 0。

## 边界

- 迁移 `202610120001_inventory_reconciliation_negative_balance` 仅移除 `inventory_balances.quantity >= 0` 的数据库检查约束。
- 正常上架出库、手工减库和入库撤销仍通过带版本条件的事务检查现有数量，不允许产生负库存。
- 常规盘点接口仍要求实际数量不小于 0。
- 负库存只能由受控的历史核对/数据迁移流程写入，并且必须同时写入不可变的 `stock_movements` 和 `audit_logs`。
- 负数是待查问题，不代表允许长期缺货销售；后续补录基准库存或盘点修正时通过新流水冲正，不能直接删除历史流水。
- 总库存台账展示所有非零批次，包括负库存审核项；总件数按正负余额净额计算，并与库存流水合计对账。
- 临期预警只统计数量大于零的批次，负库存审核项不会被误报为需要处理的临期实物。

## 升级与验证

1. 先备份目标数据库，并确认正在操作隔离库或维护窗口内的目标库。
2. 执行 Prisma migration。
3. 运行数据库集成测试，确认核对流程可保存负数。
4. 同时验证正常出库与手工减库的“库存不足”测试仍通过。
5. 导入后核对 `SUM(stock_movements.quantity_delta)` 与 `SUM(inventory_balances.quantity)`，并导出所有负库存行供人工审核。

## 回滚

重新添加非负检查约束前，必须先把所有负库存通过可审计流水修正到 0 或以上。数据库中仍存在负数时不得强行恢复约束。
