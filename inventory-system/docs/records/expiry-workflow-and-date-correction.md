# 临期处理与批次日期纠错

## 本次修改

- 入库日期筛选改为可见的原生日期输入框，支持鼠标选择与键盘输入。
- 入库记录、库存台账、库存盘点和临期预警都可以发起批次到期日期修正。
- 日期修正更新统一的商品批次，并在 `audit_logs` 保存原日期、新日期、原因和操作人。
- 相同商品已经存在目标到期日期时拒绝修正，避免自动合并两个可能不同的实物批次。
- 新增 `expiry_alert_actions`，管理者可填写、修改、忽略或软删除处理任务；员工可查看任务并标记完成。
- 删除处理任务不会删除商品批次、库存余额或库存流水。
- 临期预警表提供独立的“修改”和“删除预警”：修改用于更正批次日期；删除预警要求管理员填写原因，并将该批次从预警列表软隐藏。
- 删除预警不会改动库存、入库记录或库存流水；后续再次修改批次到期日期时，会清除软隐藏并重新参与临期判断。
- 临期范围改为累计筛选并覆盖目标月份月底：2个月包含已过期和未来2个月，3个月包含前述范围及未来3个月，6个月包含已过期至未来第6个月月底的全部库存。
- 库存流水表使用固定紧凑列宽，原因列占用剩余空间，移动端继续使用卡片布局。

## 权限与审计

- 具有盘点权限的员工可以修正批次日期，用于纠正录入错误。
- 只有门店管理员可以创建、修改、忽略或删除临期处理任务。
- 只有门店管理员可以删除临期预警；删除原因、操作者、时间以及“库存未改变”都会写入审计日志。
- 具有查看权限的员工可以将待处理任务标记为完成。
- 日期修正和临期任务状态变化都写入审计日志。

## 数据库升级

迁移：`202610120002_expiry_workflow`、`202610120003_expiry_alert_soft_hide`。

回滚时只能删除临期任务表；批次日期修正已经进入审计链，不应通过数据库回滚静默覆盖，应由新的日期修正操作恢复。
软隐藏迁移的回滚只删除 `alert_hidden_*` 字段；执行前应先导出删除原因和审计日志，避免丢失追溯信息。
