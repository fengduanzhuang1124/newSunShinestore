# 本周进货单与进货建议

## 目标

把经营分析中的库存覆盖缺口和热销商品统一汇入每店每周一张进货单。进货单只记录采购决策，不直接写入库存事实。

## 数据结构

- `purchase_orders`：门店、周起始日、单号、状态与操作人时间。
- `purchase_order_items`：商品、加入来源、加入时库存、近七天销量、建议数量、实际进货数量、供应商、进价和整箱规格。
- 同一门店同一周只能有一张进货单；同一商品在一张进货单中只能出现一次。
- 关键修改均写入 `audit_logs`。

## 状态流转

```text
DRAFT → CONFIRMED → ORDERED
  ↑         │          │
  └─────────┘          └→ 后续由到货/入库流程更新

DRAFT / CONFIRMED / ORDERED → CANCELLED
```

- `DRAFT`：可添加、修改和移除商品。
- `CONFIRMED`：锁定当前商品和数量，可退回草稿或标记已订货。
- `ORDERED`：采购已发出；本阶段不允许直接变更库存。
- `PARTIALLY_RECEIVED`、`RECEIVED` 已在模型中预留，后续由正式到货与扫码入库关联后启用。
- `CANCELLED`：保留历史，不硬删除。

## 建议口径

系统使用最近 28 个自然日中 `Paid + 无退款 + ACTIVE + INVENTORY` 的已映射 POS 销量，避免异常订单和单日偶发销量放大建议，并折算周均销量：

1. 周均低于 1 件：不自动建议；
2. 周均 1–9 件：目标覆盖 6 周；
3. 周均 10–29 件：目标覆盖 5 周；
4. 周均 30 件及以上：目标覆盖 4 周。

建议数量为“目标库存减当前正式库存”，结果最低为零。正式库存只接受事务化库存流水；POS 销售只有进入 `APPLIED` 后才完成实际扣减。页面同时展示 28 天销量、周均销量、当前覆盖周数、目标覆盖周数和目标库存，管理员可在确认前核对。

管理员可填写原因后忽略不合理建议。被忽略的建议保留在单独列表中并可恢复，忽略和恢复均写入审计日志，不修改商品、POS 或库存数据。供应商送货周期、在途数量和整箱向上取整将在后续迭代接入。

## 页面入口

- 经营总览：本周进货单摘要入口。
- 热销商品 Top 10：已映射正式商品可加入进货单。
- 库存经营：缺货和低库存行可加入进货单。
- 本周进货：集中查看进货建议、修改进货单并推动状态。

## 库存边界

加入、确认、订货或取消进货单均不会创建 `stock_movements`，也不会更新 `inventory_balances`。商品到货后必须进入现有扫码入库流程，填写批次和到期日期，正式库存才会增加。
