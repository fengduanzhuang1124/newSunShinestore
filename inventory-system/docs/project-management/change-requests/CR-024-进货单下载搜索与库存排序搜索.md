# 需求变更单：进货单按品牌下载、搜索与库存排序搜索

| 项目 | 内容 |
| --- | --- |
| 变更编号 | CR-024 |
| 关联需求 | CR-007（品牌进货单）、CR-009（本周进货单）、CR-020（库存页面） |
| 状态 | 开发完成（待门店电脑更新，无需数据库迁移） |
| 日期 | 2026-11-13 |

## 1. 变更来源

| 渠道 | 内容摘要 |
| --- | --- |
| 客户反馈（电脑截图：本周进货 · 进货建议） | 进货单需要一键下载，管理者在 Excel 中操作；品牌进货单（帕氏、coco brownie、Metoday、Haab）下载时只能包含该品牌，不能与其他品牌混在一起 |
| 客户反馈（同上） | 进货建议和已加入的进货单都需要搜索，能查到某个商品在进货单里，还是在提示进货的建议里 |
| 客户反馈（电脑截图：库存经营） | 库存排序除从高到低外还要能从低到高；要能在这里搜索某个商品的库存 |

## 2. 现状

| 编号 | 现状 |
| --- | --- |
| S1 | 进货建议页没有下载；本周进货单的“导出 Excel”导出全部商品，不区分品牌 |
| S2 | 本周进货单不显示品牌分单，看不出哪些商品属于帕氏等直采品牌 |
| S3 | 进货建议和本周进货单都没有搜索 |
| S4 | 库存经营排序只有“库存从高到低” |
| S5 | 库存经营“筛选当前结果”不能按条码查，而且会漏掉已忽略、下周显示和直发商品，也受上方状态标签（滞销、缺货等）限制，容易查不到 |

## 3. 变更内容

| 编号 | 内容 | 规则 |
| --- | --- | --- |
| F1 | 进货建议一键下载 | 进货建议页增加“下载 Excel”，导出当前品牌进货单、当前标签（全部 / 本周优先 / 后续跟进 / 已忽略）的全部商品（搜索只筛选屏幕，不影响下载，避免漏单）：品牌、商品、条码、当前库存、周销量、可卖、建议进货、优先级、是否已加入进货单、说明。文件名带品牌名，如“帕氏进货建议-2026-11-13.xls” |
| F2 | 本周进货单按品牌分单 | 本周进货单显示与进货建议相同的品牌分单（总进货单、帕氏、coco brownie、Metoday、Haab）及件数；“导出 Excel”和“预览”只包含当前品牌的商品，文件名带品牌名。品牌判断与进货建议一致（CR-007） |
| F3 | 进货建议与进货单搜索 | 两处都增加搜索框，可按商品名、品牌、条码、SKU 查找；两处共用同一个搜索词。搜索时同时提示另一处的匹配数，例如“本周进货单中也有 2 项”，点击即切换过去，便于确认商品在进货单里还是在建议里 |
| F4 | 库存从低到高 | 库存经营排序增加“库存从低到高” |
| F5 | 库存搜索 | “筛选当前结果”改为“搜索商品”，可按名称、品牌、分类、SKU、条码查找；输入搜索词时自动切到“全部”状态，已忽略、下周显示和直发商品也能查到并注明状态；当前结果中查不到时，提供“在全部商品中查询”，查询零库存且近期无销售的商品 |

## 4. 不改变的内容

- 进货建议算法、品牌分单规则、进货单状态流程不变。
- 下载文件为本地 Excel 文件，在 Excel 中修改不会回写系统；系统内的进货数量仍以页面保存为准。

| 上线 | 门店电脑停服务 → `git pull` → `corepack pnpm build` → `corepack pnpm start:prod`；无数据库迁移 |

| 编号 | 验收内容 |
