# 需求变更单：点货提交提示与入库单按商品合并

| 项目 | 内容 |
| --- | --- |
| 变更编号 | CR-023 |
| 关联需求 | CR-016（多人同时点货）、REQ-010（扫码入库） |
| 状态 | 开发完成（待门店电脑更新，无需数据库迁移） |
| 日期 | 2026-11-10 |

## 1. 变更来源

| 渠道 | 内容摘要 |
| --- | --- |
| 客户反馈（手机截图） | 员工账号和管理员账号同时分工点货，管理员账号“确认整单入库”按钮变灰无法点击，页面没有任何说明 |
| 客户确认 | 两个账号各点各的货，同一商品同一日期允许相加；入库后同一商品不管日期是否相同都要合并成一条，不要分成多条 |
| 正式库只读核查 | 当天员工账号入库单 87 行、2147 件，其中同一商品因到期日期不同或多次提交分成多行；管理员账号没有任何入库提交，清单中有若干行与员工当天已入库的商品、日期相同 |

## 2. 原因

| 编号 | 原因 |
| --- | --- |
| C1 | 清单中有商品在相同到期日已有库存时，需逐行选择“新到货（相加）”或“重新点货”，未选完按钮变灰，但页面不提示原因 |
| C2 | “该日期已有 N 件”不区分是今天其他账号刚入库的，还是原有库存，无法判断是否同一批货 |
| C3 | 入库单按“商品 + 到期日期”分行，同一商品不同日期显示为多行 |

## 3. 变更内容

| 编号 | 内容 | 规则 |
| --- | --- | --- |
| F1 | 按钮不可用时写明原因 | 清单下方显示原因：“还有 N 项需要选择新到货（相加）或重新点货”或“有 N 项数量不正确”；需要选择的行加醒目边框 |
| F2 | 一键全部相加 | 有待选择的行时显示“全部按新到货相加”，一次把未选择的行都设为相加；已手动选择的行不改变 |
| F3 | 区分今天已入库的数量 | “该日期已有 N 件”后注明“其中今天 员工1 已入库 X 件”，便于分工点货时判断是不是同一批货 |
| F4 | 入库单按商品合并 | 入库记录和导出中，同一张入库单内同一商品合并为一行，数量相加；到期日期列出每个日期及件数（如 2033-11 × 44、2034-11 × 6）；每个日期仍可单独修正日期。库存仍按到期日期分批保存，临期提醒不受影响 |

| 编号 | 验收内容 |

| A1 | 清单有未选择的行时，按钮下方显示原因和待选数量；点“全部按新到货相加”后按钮可点击 |
