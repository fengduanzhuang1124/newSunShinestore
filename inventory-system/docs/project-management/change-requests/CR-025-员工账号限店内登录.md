# 需求变更单：员工账号限店内登录

| 项目 | 内容 |
| --- | --- |
| 变更编号 | CR-025 |
| 关联需求 | REQ-008（经营管理手机适配）、CR-013（单端口正式运行与外网访问） |
| 状态 | 开发完成（待门店电脑更新，需数据库迁移） |
| 日期 | 2026-11-13 |

## 1. 变更来源

| 渠道 | 内容摘要 |
| --- | --- |
| 客户提问（对话） | 员工账号 wf66 能否做到：任何人的手机都可以登录，但只限在店内使用 |
| 客户追问（对话） | 不连接店内 Wi-Fi 能否限制 |
| 客户要求（对话） | 员工账号不能在家里登录，需要给出设置 |

## 2. 现状与方案选择

| 编号 | 内容 |
| --- | --- |
| S1 | 系统现在没有任何登录地点限制：账号密码正确，在任何地方都能通过外网地址登录 |
| S2 | 门店外网访问经 Tailscale Funnel 中转，服务器看到的来源地址都是本机，不能按 IP 或店内 Wi-Fi 判断 |
| S3 | 采用手机定位判断：登录时由浏览器取得位置，服务器计算与门店的距离，超出范围拒绝登录。不依赖店内 Wi-Fi，任何手机都可使用 |

## 3. 变更内容

| 编号 | 内容 | 规则 |
| --- | --- | --- |
| F1 | 门店位置设置 | 数据中心增加“登录限制”页（仅管理员）。管理员在店内点“用当前位置设为门店位置”，或手工填写经纬度（可从地图复制）；允许范围可选 100 / 200 / 300 / 500 / 1000 米，默认 300 米 |
| F2 | 账号开关 | 同一页列出本门店的账号，每个员工账号可开关“仅限店内登录”；管理员账号不能开启，避免把管理员锁在门外 |
| F3 | 登录检查 | 开启限制的账号登录时，页面请求定位权限；在门店范围内才能登录。范围外提示“该账号只能在门店内登录（当前距离门店约 X 公里）”；拒绝定位、定位失败或精度差于 1 公里时提示开启精确定位；门店未设置位置时提示联系管理员 |
| F4 | 留痕 | 门店位置、范围和账号开关的修改记入审计日志；范围外的登录尝试记入审计日志（含距离），便于管理员查看 |

## 4. 限制与说明

- 只在登录时检查位置。登录后的会话按现有规则 8 小时有效，员工在店内登录后离店，最长 8 小时内仍可使用；需要立即停止时，管理员可修改该账号密码（后续可另行增加“强制下线”）。
- 浏览器只在 HTTPS 地址下提供定位：员工须使用 `https://node.tail10ff0a.ts.net`，不能使用店内 `http://IP:端口` 地址。
- 定位来自手机浏览器，技术上可被专门工具伪造；本功能用于日常管理，不作为高安全级别的防护。
- 已登录且未过期的会话不受影响，上线后开启限制的账号下次登录时才生效。

## 5. 数据库变更

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `users` | `in_store_only` TINYINT(1) NOT NULL DEFAULT 0 | 是否仅限店内登录；默认 0，现有账号不受影响 |
| `stores` | `latitude` DECIMAL(9,6) NULL、`longitude` DECIMAL(9,6) NULL | 门店位置；为空表示未设置 |
| `stores` | `login_radius_m` INT UNSIGNED NOT NULL DEFAULT 300 | 允许登录的范围（米） |

迁移只新增字段并带默认值，旧版本代码可继续运行。回滚：删除以上 4 个字段，并删除 `_prisma_migrations` 中对应记录。

## 6. 接口

| 方法与路径 | 权限 | 说明 |
| --- | --- | --- |
| `POST /api/v1/auth/login` | 公开 | 增加可选 `latitude`、`longitude`、`accuracy`；开启限制的账号未带位置时返回 HTTP 428，页面取得定位后自动重试 |
| `GET /api/v1/management/login-settings?storeId=` | 管理员 | 门店位置、范围与本门店账号列表 |
| `POST /api/v1/management/login-settings/store?storeId=` | 管理员 | 保存门店位置与范围 |
| `POST /api/v1/management/login-settings/user?storeId=` | 管理员 | 开关某账号的“仅限店内登录” |

## 7. 上线与回滚

| 步骤 | 内容 |
| --- | --- |
| 上线 | 门店电脑备份数据库 → 停服务 → `git pull` → `packages\database` 下 `corepack pnpm exec prisma migrate deploy` → `corepack pnpm build` → `corepack pnpm start:prod`；管理员在店内用手机打开“数据中心 → 登录限制”，设置门店位置，再给员工账号开启限制 |
| 回滚 | 先在“登录限制”中关闭所有账号的限制即可立即恢复；需要回退代码时回到上一版本重新构建，字段可保留 |
