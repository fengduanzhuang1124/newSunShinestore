# 需求变更单：正式运行方式与图片压缩

| 项目 | 内容 |
| --- | --- |
| 变更编号 | CR-013 |
| 关联需求 | REQ-008（性能 M7） |
| 状态 | 开发完成（待门店电脑切换，无需数据库迁移） |
| 日期 | 2026-11-02 |

## 1. 变更来源

| 渠道 | 内容摘要 |
| --- | --- |
| 客户反馈 | 其他人的电脑打开公网网址很慢，怀疑是 Tailscale 的原因 |
| 门店电脑排查结论 | 主要原因是正式环境用的是开发模式（`pnpm dev`）：页面文件不打包、不压缩，浏览器要逐个请求 80 多个文件，每个都要经公网中转；其次是 logo 和助手图片为未压缩的 PNG（0.6–2.4 MB）；Tailscale Funnel 本身也不保证速度 |
| 客户确认 | 代码在 Mac 上修改、测试、推送，门店电脑只拉取运行 |

## 2. 变更内容

| 编号 | 内容 | 规则 |
| --- | --- | --- |
| F1 | 正式运行方式 | 新增启动命令 `corepack pnpm start:prod`：由 API 服务（端口 3100）同时提供打包后的管理端页面和接口，页面与接口同一地址，沿用已有的 gzip 压缩；开发模式 `corepack pnpm dev` 保持不变 |
| F2 | 缓存 | 打包后带版本号的文件（`/assets/`）浏览器缓存一年，更新后文件名会变，不会用到旧文件；入口页 `index.html` 每次都向服务器确认；其他图片缓存一天 |
| F3 | 访问来源 | 允许从 API 端口（3100）打开的页面调用接口，其余来源规则不变 |
| F4 | 图片压缩 | 登录页和页头 logo、阳光小助手图标改为按实际显示尺寸缩小的 WebP，画面不变 |
| F5 | 公网入口 | Funnel 改为指向 `http://localhost:3100`；门店电脑由客户执行切换命令 |

## 3. 不在本次范围

- 公网入口换成 Cloudflare Tunnel：需要 Cloudflare 账号和自有域名，客户决定后另开变更单。
- 未被页面使用的旧图片暂不删除。

## 4. 上线与回滚

| 步骤 | 内容 |
| --- | --- |
| 上线 | 门店电脑停服务 → `git pull` → `corepack pnpm install` → `corepack pnpm build` → `corepack pnpm start:prod` → Funnel 改指向 3100 → 公网网址登录测试 |
| 回滚 | 停 `start:prod`，执行 `corepack pnpm dev`，Funnel 改回 `https+insecure://localhost:5174`；不涉及数据库 |

## 5. 验收

| 编号 | 验收内容 |
| --- | --- |
| A1 | `start:prod` 下首页、登录、各管理页面和接口正常 |
| A2 | 页面文件为打包压缩版本，请求数明显减少；图片总大小明显下降 |
| A3 | 开发模式不受影响；API、管理端测试与构建通过 |
