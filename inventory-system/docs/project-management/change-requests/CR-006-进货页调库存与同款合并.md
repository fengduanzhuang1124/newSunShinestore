# 需求变更单：进货页调库存、同款合并与进货建议规则调整

| 项目 | 内容 |
| --- | --- |
| 变更编号 | CR-006 |
| 关联需求 | 进货建议（CR-005）、REQ-012（盘点）、REQ-013（POS 商品对应） |
| 提出日期 | 2026-10-26（客户反馈） |
| 状态 | 开发完成（待上线） |

## 1. 变更来源

| 日期 | 渠道 | 内容摘要 |
| --- | --- | --- |
| 2026-10-26 | 客户反馈 | 盘点完成后，进货建议中部分商品库存显示与实点不符：同一商品存在多份档案（如 Swisse 护肝 120 粒有 3 份），点数记在一份、进货建议显示另一份 |
| 2026-10-26 | 客户反馈 | 漏点的商品希望在进货页直接调整库存，不必回到库存系统 |
| 2026-10-26 | 客户反馈 | 实际进货单与系统“本周优先”差异：慢销商品需保持陈列量；系统“本周优先”标准偏紧 |
| 2026-10-26 | 甲方确认 | 以下 4 项按建议全部实施 |

## 2. 变更内容

| 编号 | 变更 | 规则 |
| --- | --- | --- |
| D1 | 进货页“调库存” | 进货建议每行增加“调库存”：显示该商品现有批次（到期日、数量），可改数量、改到期日、增删批次；确认后按盘点同样的规则对齐批次，记库存流水（来源“进货页调库存”）与审计；有版本校验，期间库存变化会提示刷新；同一请求不会重复入账 |
| D2 | 同款合并 | 进货建议每行增加“合并同款”：按名称或条码搜索同一商品的其他档案，选择后确认合并。库存处理二选一：①以当前商品库存为准（被合并档案库存清零，适用于重复盘点）；②库存相加（按到期日并入）。被合并档案的条码、POS 对应、销售记录转入当前商品，档案停用；写审计。合并前显示双方库存、条码与 POS 名称 |
| D3 | 慢销品陈列量 | 每周销量不足 1 件、但近 90 天有销售的商品：库存低于陈列量时建议补到陈列量。陈列量 = 商品设置的最低库存，未设置时为 2 件 |
| D4 | “本周优先”标准 | 由“可卖不足 1 周”改为“可卖不足 2 周”（缺货、低于最低库存仍为本周优先） |

## 3. 影响评估

| 方面 | 影响 |
| --- | --- |
| 数据库 | 无结构变更 |
| 库存 | D1、D2 写库存流水，与盘点、档案合并同等规则；不影响其他商品 |
| POS 扣库 | D2 合并后 POS 扣减统一到保留的档案；每小时的对应刷新按条码归属保持 |
| 进货建议 | D3 使慢销商品出现在建议中；D4 使“本周优先”数量增加 |
| 上线 | 合并代码即可，无迁移 |
