## 2. 现状（代码与数据核查）

| 项目 | 现状 |
| --- | --- |
| POS 扣库依据 | 按 POS 商品编号查“商品对应”，有对应才扣减；对应关系通过条码把 POS 商品与库存商品连起来 |
| POS 商品目录 | 系统已能读取 POS 完整商品目录（含条码、名称、售价），无需甲方手工导出 |
| 条码 | 一个商品可有多个条码；同一条码只能属于一个商品（数据库唯一约束） |
| 杂项 | POS 杂项行的商品编号为 0，名称为收银员输入的文字（如 `MISC_muguagao25`）；目前一律视为非库存，不扣减 |
| 规模 | 盘点清单中 POS 未对应 66 种（已盘点 12、待盘点 54）；近 28 天杂项中可识别为商品的约 60 件 |

## 3. 目标

1. 66 种未对应商品在盘点时扫码即可完成对应，不需要另找电脑操作。
2. POS 无法区分的商品通过杂项代码也能扣库存。
3. 每天自动列出商品总表的缺口，当天发现、当天处理。

## 4. 范围与规则

### 4.1 手机扫码对应（P1）

在盘点面板中，POS 未对应的商品显示“扫码对应”按钮：

| 扫到的条码 | 处理 |
| --- | --- |
| 已是该商品的条码，且 POS 目录中有该条码 | 直接建立对应 |
| 不是该商品的条码，也不属于其他商品 | 作为该商品的新增条码保存，再在 POS 目录中查找并对应 |
| 已属于其他商品 | 不保存，提示“该条码属于 XXX”，由甲方判断是否重复档案 |
| POS 目录中没有该条码 | 条码照常保存；提示“POS 中没有此条码”，可选：在 POS 商品中按名称搜索并手工选择对应 / 设为直邮 / 不再销售 |

- 对应完成后，面板继续盘点数量与到期日，流程与现有盘点相同。
- 对应生效后，该商品在盘点确认之后的 POS 销售，通过现有“复核补扣”自动补扣（盘点确认之前的销售已被盘点覆盖，不再扣）。
- 所有新增条码与对应写审计。

### 4.2 杂项代码（P2）

- 在经营管理中维护“杂项代码表”：代码 → 商品（例：`MG25` → Lucas 木瓜膏 25g）。
- 收银时杂项名称输入 `MISC_` + 代码；系统同步时识别代码（不区分大小写，忽略空格），按对应商品扣减。
- 未登记的代码、运费、手续费仍按非库存处理；未登记的杂项文字进入日常检查清单。
- 可从近期杂项销售中直接选取已出现的文字建立代码。

### 4.3 日常自动检查（P3）

每天自动生成，在首页（管理员）显示待处理数量，在“经营管理 → 数据中心”中查看明细：

| 检查项 | 说明 |
| --- | --- |
| POS 卖出但未对应 | 昨日及以前未对应的销售行，按 POS 商品汇总 |
| 未登记的杂项文字 | 无法识别为商品的杂项行 |
| 有库存但 POS 未对应 | 库存系统有库存、POS 目录无对应的商品（直邮、不再销售除外） |
| POS 新商品 | POS 目录中新出现、库存系统尚无档案的商品 |
| 疑似重复档案 | 名称高度相似或同品牌同规格的多个档案 |
| 负库存 | 余额小于 0 的商品 |

每项可直接处理（对应、建档、设直邮、不再销售、标记已核实）；已处理的不再重复出现。

## 5. 不包含

- 修改 POS 系统中的商品资料（POS 侧新增或改条码由甲方在 POS 后台操作）。
- 放开“同一条码只属于一个商品”的限制（共用条码的商品用杂项代码区分）。

## 7. 验收标准

1. 盘点面板扫码后，商品显示“已对应 POS”，审计中有记录；之后 POS 卖出该商品会扣库存。
2. 扫到属于其他商品的条码时不保存，并提示归属商品。
3. 登记杂项代码后，POS 输入 `MISC_代码` 的销售按对应商品扣减；未登记的出现在检查清单。
4. 日常检查每天生成，首页显示待处理数量，处理后不再重复出现。
5. 现有 POS 扣库、盘点、进货建议行为不变；自动测试与演练库验证通过。

### 4.1 实现说明（与第 4.1 节的差异）

核查发现：系统每小时从 POS 商品目录按条码更新对应，POS 中出现未知条码时会自动建一个商品档案。因此“POS 未对应”的商品，大多是 POS 用了另一个条码，从而被自动建成了另一份档案（例：高之源 200 粒维 C，系统条码 941025564598，POS 条码 9421025564598）。实现据此调整，不新增数据表：

| 扫到的条码 / 选择 | 处理 |
| --- | --- |
| 新条码 | 保存到当前商品；提示 POS 中没有此条码，可按名称搜索 POS 商品 |
| 属于另一档案 | 先显示该档案名称、POS 名称与库存，确认后合并：条码、POS 对应、销售记录转到当前商品，该档案库存清零（以本次盘点为准，记 `PRODUCT_MERGE` 流水）并停用；写审计 |
| 另一档案本次已盘点且有库存 | 不允许在手机上合并，提示在电脑上核对 |

接口：`GET /inventory/count-tasks/:taskId/pos-products?q=`、`POST /inventory/count-tasks/:taskId/items/:itemId/pos-link`。页面：盘点页顶部“POS 未对应 N 种”入口，面板内“扫码对应 / 输入条码 / 按名称找 POS 商品”。合并后，盘点确认之后的销售可在复核明细中补扣。
