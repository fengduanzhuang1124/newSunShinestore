## 1. 需求来源

| 日期 | 渠道 | 内容摘要 |
| --- | --- | --- |
| 2026-10-21 | 需求评审 | 经营管理端需按主流手机 App 尺寸与交互习惯适配移动设备 |
| 2026-10-22 | 客户反馈 | 移动端经营管理页面内容超出屏幕高度，底部导航区域未适配 |

佐证材料：客户提供的移动端截图两份（库存经营页长时间停留在加载状态；筛选区纵向堆叠占满首屏）。

## 2. 背景与问题

经营管理端（`ManagementDashboard.vue`）按电脑屏幕设计，手机端靠 17 个 `@media(max-width:720px)` 块和全局样式逐层覆盖实现，存在以下问题：

| 编号 | 问题 | 表现 | 原因（代码层面） |
| --- | --- | --- | --- |
| P1 | 页面高度超出屏幕 | 内容与底部导航重叠或被遮挡；部分区域出现双重滚动 | 页面使用固定高度与 `vh` 计算，未按 iPhone 动态视口（`dvh`）与安全区计算；内容区底部留白与底部导航实际高度不一致 |
| P2 | 底部功能区不适配 | 底部导航在不同机型位置与高度不一致，与 iPhone 底部横条冲突；“更多”面板遮挡内容 | 导航高度、内边距与安全区在多处分别定义，互相覆盖 |
| P3 | 宽表格在手机上挤压 | 商品明细、库存经营、进货单、数据中心表格横向挤压或需横向滚动 | 表格只做了缩放，没有手机布局 |
| P4 | 首屏信息效率低 | 筛选条件、按钮、说明文字纵向堆叠，关键数字被挤到首屏以下 | 电脑端的筛选栏在手机上整列铺开 |
| P5 | 加载慢、无加载骨架 | 长时间只显示“正在更新…” | 单次数据量大（库存经营已从 2.7 MB 降至 0.9 MB，仍可再压缩）；接口未开启 gzip |
| P6 | 视觉不一致 | 字号、间距、圆角、卡片样式各页不同；部分按钮小于手指可点范围 | 样式分散在全局 `styles.css` 与组件内长样式行，没有统一规范 |
| P7 | 页面说明文字过期 | 库存经营“页面说明”仍写“最近120天”“默认20件” | 规则变更（CR-001、CR-002）后未同步文案 |

## 3. 目标

1. 在常见 iPhone 与安卓手机上，经营管理每个页面都能在一屏宽度内完整、清晰地使用，无横向滚动、无遮挡。
2. 达到“正常手机 App”的观感与操作习惯：固定顶部栏、固定底部导航、内容区独立滚动、卡片式信息、底部弹出筛选。
3. 首屏 2 秒内显示关键数字（4G 网络、数据已缓存于服务器）。
4. 建立一套手机端视觉规范，后续页面按同一规范开发。

## 4. 范围

### 4.1 包含

- 经营管理端全部页面的手机布局：总览、销售、商品、库存经营、本周进货、数据中心，以及“更多”中的客户标签、门店对比。
- 顶部栏、底部导航、“更多”面板、筛选面板、加载/空/失败/无权限四种状态。
- 接口响应压缩（gzip）。
- 页面说明文字与当前规则一致（P7）。

### 4.2 不包含

- 库存管理端（员工入库、出库、盘点页面）的整体手机重做（REQ-007 已处理入库表单；其余另行立项）。
- 业务规则、统计口径、数据库结构的任何变化。
- PWA“添加到主屏幕”与原生 App 打包（作为后续独立需求，见第 12 节）。
- 平板与横屏专门设计（保证可用，不做专门优化）。

## 5. 设计规范（美观性要求）

### 5.1 设计原则

1. **一屏一个重点**：每页首屏只放最重要的 2–4 个关键数字和一个主操作。
2. **拇指可达**：主导航和主操作放在屏幕下半部；危险操作远离常用按钮。
3. **信息分层**：标题 → 关键数字 → 列表 → 次要说明，层级靠字号与字重区分，不靠颜色堆叠。
4. **状态不只靠颜色**：缺货、低库存、滞销等状态同时用文字标签表达，色弱用户也能区分。
5. **与电脑端同源**：沿用现有深色/浅色主题和品牌色，手机端是同一产品的紧凑版，而不是另一套风格。

### 5.2 屏幕与布局网格

| 项目 | 规范 |
| --- | --- |
| 设计基准宽度 | 390 px（iPhone 14/15），兼容 375 px（iPhone SE/mini）至 430 px（Pro Max） |
| 页面左右边距 | 16 px（≤ 375 px 宽时 12 px） |
| 间距体系 | 4 px 基准：4 / 8 / 12 / 16 / 24 |
| 页面高度 | 以 `100dvh` 为准；顶部栏与底部导航固定，内容区单独滚动，禁止双重滚动 |
| 安全区 | 顶部加 `env(safe-area-inset-top)`，底部导航加 `env(safe-area-inset-bottom)` |
| 顶部栏 | 高 52 px：左侧页面标题，右侧门店/账号入口；滚动时保持可见 |
| 底部导航 | 高 56 px + 底部安全区；5 个入口（总览、销售、商品、库存、更多），图标 22 px + 文字 11 px；当前项高亮并有底色胶囊 |
| 内容区底部留白 | 底部导航高度 + 安全区 + 16 px，保证最后一张卡片完整可见 |

### 5.3 字体与数字

| 用途 | 字号 / 行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 20 / 28 | 600 |
| 卡片标题 | 15 / 22 | 600 |
| 关键数字 | 24 / 30（等宽数字 `tabular-nums`） | 700 |
| 正文 | 14 / 20 | 400 |
| 辅助说明 | 12 / 16 | 400 |
| 最小字号 | 12 px（输入框 16 px，避免 iPhone 自动放大） | — |

长商品名最多两行，超出以省略号结束；条码使用等宽字体。

### 5.4 颜色

- 沿用现有主题色（深色背景 `#0d1726` 系、浅色 `#f7f9fc` 系与品牌渐变），不新增主色。
- 状态色统一：正常（绿）、低库存（琥珀）、缺货（红）、滞销关注（青）、POS 未映射（橙），每种配浅色底与文字标签。
- 文字与背景对比度不低于 4.5:1（正文）与 3:1（大号数字）。

### 5.5 组件

| 组件 | 规范 |
| --- | --- |
| 关键数字卡 | 2 列网格，圆角 14 px，内边距 12 px；上方小标题，中间大数字，下方一行说明；可点击的卡片右上角带箭头 |
| 列表卡片（替代宽表格） | 每行一张卡：第一行商品名（两行内），第二行品牌·品类，右侧状态标签；底部一行 3 个关键数字（库存 / 销量 / 日均）；操作按钮收在卡片右下角“⋯” |
| 分段切换 | 页面内二级切换（如缺货 / 低库存 / 滞销）使用横向可滑动的分段控件，当前项实心高亮，带数量角标 |
| 筛选面板 | 页面右上“筛选”按钮打开底部弹出面板（圆角 20 px 顶部、拖拽条），包含日期、品牌、品类、排序；底部固定“重置 / 应用”两个按钮 |
| 按钮 | 主按钮高 44 px、圆角 12 px；可点击区域不小于 44 × 44 px |
| 加载 | 骨架屏（卡片灰色占位，轻微闪动）替代纯文字“正在更新…” |
| 空 / 失败 / 无权限 | 图标 + 一句说明 + 一个操作按钮（重试 / 去设置 / 联系管理员），四种状态样式统一 |
| 动效 | 页面切换与面板弹出 200–250 ms，遵守系统“减少动态效果”设置 |

## 8. 影响评估

| 方面 | 影响 | 说明 |
| --- | --- | --- |
| 数据库 | 无 | — |
| 接口 | 无内容变化 | 新增 gzip 压缩；如列表改为服务端分页将另行登记变更单 |
| 页面 | 有 | 经营管理全部页面的手机布局；电脑端布局保持不变 |
| 权限 | 无 | — |
| 依赖 | 有 | 新增 `compression` 中间件 |
| 性能 | 改善 | 压缩后库存经营响应预计由约 0.9 MB 降至约 0.1 MB |
| 风险 | 中 | 改动面大，若继续在现有 1,756 行单文件上叠加样式会重蹈覆盖问题；见第 9 节建议 |

## 9. 实施方案

**建议与 REQ-011（大文件拆分）合并实施**：先把 `ManagementDashboard.vue` 按页面拆成独立组件（总览、销售、商品、库存经营、进货、数据中心、更多），再为每个页面按本规范编写手机布局。这样新样式写在各自组件里，不再在 6,744 字符的单行模板和 1,741 行全局样式上叠加覆盖层。

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| 1 | 基线截图：三种尺寸逐页截图，记录现状问题 | 测试报告“改造前”截图 |
| 2 | 拆分页面组件（REQ-011 中经营管理部分），行为不变 | 新旧结果比对通过 |
| 3 | 页面骨架、顶部栏、底部导航、“更多”面板（M1、M2） | 三种尺寸截图 |
| 4 | 关键数字卡、列表卡片、筛选面板、四种状态（M3–M6、M8） | 组件测试 + 截图 |
| 5 | gzip 与文案（M7、M9） | 响应头与计时记录 |
| 6 | 真机验收与甲方确认（A1–A9） | 测试报告与部署记录 |

预计工作量：阶段 1–2 约 1 个工作单元，阶段 3–5 约 2 个工作单元，阶段 6 视反馈 0.5 个工作单元。

## 10. 测试方案

- 自动测试：现有测试全部通过；新增底部导航、列表卡片、筛选面板组件测试。
- 截图测试：使用无头 Chrome 在三种尺寸逐页截图，改造前后对比存档于 `outputs/`（截图含业务数据，不提交 git）。
- 真机测试：iPhone Safari、微信内置浏览器各走查一遍主要页面。
- 截图方式：使用模拟数据在本机渲染各页面（与组件测试同源的固定样例数据），无需登录正式系统，截图不含真实业务数据，可随测试报告存档。

## 11. 上线与回滚

- 上线：经甲方确认后提交并合并到运行目录，前端热更新、API 自动重启（无数据库变更）。
- 回滚：`git revert` 对应提交；gzip 可单独关闭。
