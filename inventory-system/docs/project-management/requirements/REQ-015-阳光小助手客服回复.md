## 1. 需求来源

| 渠道 | 内容摘要 |
| --- | --- |
| 客户反馈 | 微信个人号和群聊无法接入官方智能客服；希望在管理系统里放一个小机器人，客服把客户问题复制粘贴进去，机器人给出回复，客服再复制回微信 |
| 客户提供的参考方案 | 先整理高频问答和客服语气、建立知识库，价格、库存、到期日实时查询系统，不先训练模型；第一版做内部"客服回复工作台"，记录客服对回答的处理 |
| 客户提供的界面参考 | 深色玻璃输入框，紫到橙渐变发光边框；发送后移到页面右侧成为整列问答栏（类似浏览器侧边 AI 栏）；提问以发光气泡显示 |
| 客户确认 | 入口在每个页面标题栏右上角，文字"问问阳光小助手"；问答栏宽度和输入框高度可拖动；切换页面不影响问答；不能与页面内容叠放；不要麦克风；先做界面，问答整理随后提供 |
| 客户提供问答整理与奶粉价格单 | 常见问法与回答（有货、价格、日期、发货时效、证件等）；11 月 2 日更新的邮寄奶粉价格单（纽币，婴儿奶粉为 3 罐包邮价，分普通线与顺丰线，含保质期、发货地点、偏远地区运费） |
| 客户确认（阶段 2 规则） | 店内商品价格用第 4 级价格（即零售价）；日期列出库存里的全部日期和库存数给客服看，回复客人只说最早的日期和"有货"，不说数量；邮寄奶粉按价格单回答，按普通线 / 顺丰线、段数、罐数或袋数区分；店内有条码的单罐奶粉不能邮寄，回复不得说可以邮寄；回复语气温和，多用"哦～""哈～" |
| 客户确认 | 经营总览去掉"刷新今日数据"按钮（系统自动刷新）；"经营日期"移到"库存更新、POS 最近成功同步"同一行并靠右 |

| 项目 | 现状 | 问题 |
| --- | --- | --- |
| 页面标题栏右侧 | 只有经营总览有"经营日期"和"刷新今日数据"，数据中心有"刷新状态"，其余页面为空 | 各页面不统一，没有放置全局工具的位置 |

## 4. 范围与限制

- 本需求只在经营管理内使用，不对顾客开放，不接入微信。
- 阶段 1 不新增接口和数据表，不需要数据库迁移。对话只保存在本浏览器的本次会话内，关闭标签页即清除。
- 是否需要按角色限制谁能看到小助手，阶段 2 与问答库一起确定；阶段 1 所有能进入经营管理的账号都可见。

## 6. 阶段 2：按系统数据生成建议回复

### 6.1 两类商品，回答规则不同

| 类别 | 怎么认 | 价格 | 日期 | 能否邮寄 |
| --- | --- | --- | --- | --- |
| 店内商品（含店内单罐奶粉） | 其余在售商品，有真实条码 | 门店零售价（即 POS 第 4 级价格；POS 同步每小时刷新） | 本店仓库库存大于 0 的批次中最早的到期日期 | 不能。客人问邮寄时回复"店内商品不能邮寄"，并提示客服改推邮寄款 |
| 邮寄奶粉 | POS 里名称带奶粉品牌和包装写法的商品，如 `karicare goat 1 3tins`、`Karicare Goat SF 1* 6tins`、`Anchor Full cream 1kg SF *6`（POS 里的"条码"是内部编号，不能用来区分） | 该 POS 商品的零售价 | 不录入（随批次经常变化）；客人问日期时回复"日期帮您确认一下哦～"并标记需人工，由客服向仓库确认 | 可以；发货地按设置（新西兰 / 澳洲） |

客户确认不再导入价格单 Excel：邮寄奶粉的价格在 POS 里已有，与价格单一致；POS 没有的线路、包装、时效、发货地和活动在小助手设置里维护；保质期不录入。

### 6.2 回复内容

每条结果分两部分：

| 部分 | 内容 |
| --- | --- |
| 给客人的回复（复制即采用） | 例："有货哦～日期是28年5月哈～"；"可瑞康山羊奶粉 1段：普通线 3罐 168纽币包邮，6–8周到哈～顺丰线 6罐 375纽币，7–10个工作日到哈～"；"安佳全脂奶粉：顺丰线 6袋 115纽币，买一箱立减5纽币，到手110纽币，7–10天到哈～" |
| 客服参考（默认展开，只给客服看） | 店内商品：零售价、库存合计、每个到期日期及其库存数；邮寄奶粉：同一款的各线路、包装、价格、活动、时效、发货地；不确定时列出候选商品（点击即按该商品重新查询）；提醒事项 |

规则：
- 给客人的回复不出现库存数量；有多个日期只说最早的。
- 店内库存为 0 时回复"暂时没货哦～"。
- 邮寄奶粉设为断货或没有价格的，不报价，标记"需人工确认"；问邮寄奶粉日期的，标记需人工并提醒客服向仓库确认。
- 客人说了线路（顺丰 / SF / 普通线）或包装（罐 / 袋）时只报对应的，否则列出全部。
- 婴儿奶粉没说段数且多个段数都可能时，追问"亲要几段的呢～"；相近商品只差规格时追问"亲要120粒还是200粒的呢～"；问了规格（如 200粒）时排除只有其他规格的商品；同名的多个商品只有一个有库存时按有库存的回答，并提醒客服另有同名商品；其余情况请客人发图片或完整名字，候选商品列在客服参考里，客服点击候选即按该商品回答原问题。
- 近 14 天有低于零售价的售出时，提醒客服确认是否有活动。
- 孕妇、哺乳、过敏、疾病、用药、不良反应、投诉、退款等问题只回复"转给专业的同事确认"，并标记需人工。
- 偏远地区运费等固定说明由管理员在"固定回复"里维护，问题出现关键词时附在回复后。
- 证件照片等个人信息只由客服人工处理，小助手不接收、不保存。

### 6.3 数据表（只新增 4 张表，现有表不加字段）

迁移：`202611020001_assistant_replies`（升级说明与回滚语句写在迁移文件内）。

| 表 | 内容 |
| --- | --- |
| `mail_milk_profiles` | 每个邮寄奶粉 POS 商品一行：回复里的名称、线路、段数、包装数量和单位、时效、发货地、活动说明和减价、是否断货、是否启用（不含保质期）。由"从 POS 识别"自动生成，管理员核对修改；按价格单默认：贝拉米、雅培、美可卓蓝胖子及名称带 AU 的为澳洲发货，安佳全脂 / 脱脂袋装带"买一箱立减5纽币"（减 5 纽币） |
| `assistant_aliases` | 客人叫法 → 商品名称里的词（如"蓝胖" → maxigenes）；另有一组系统自带叫法（爱他美 → aptamil、铂金 → pro 等） |
| `assistant_answers` | 固定回复：主题、关键词、回复内容、是否转人工、是否启用 |
| `assistant_reply_logs` | 问题原文、识别的问题类型、建议回复、客服参考、是否需人工、客服处理结果（复制采用 / 修改后采用 / 不采用 / 转人工）及修改后的文字；不保存客人姓名、电话、证件 |

设置的新增和修改都写审计日志。

### 6.4 接口

均需登录并有该门店权限；提问和反馈对门店员工开放，设置仅管理员。

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/assistant/replies?storeId=` | 提交客人问题，返回建议回复、客服参考、是否需人工 |
| `POST /api/v1/assistant/replies/:id/feedback?storeId=` | 记录客服处理结果 |
| `GET /api/v1/assistant/mail-milk?storeId=` | 邮寄奶粉设置列表（含 POS 价格）及尚未设置的数量 |
| `POST /api/v1/assistant/mail-milk/detect?storeId=` | 从 POS 商品识别新的邮寄奶粉，已有设置不变 |
| `PATCH /api/v1/assistant/mail-milk/:productId?storeId=` | 修改一个邮寄奶粉设置 |
| `GET/POST /api/v1/assistant/aliases`、`PATCH /aliases/:id` | 客人叫法 |
| `GET/POST /api/v1/assistant/answers`、`PATCH /answers/:id` | 固定回复 |

### 6.5 处理顺序

`assistant.service.ts` 按顺序调用 `assistant-rules.ts` 里的独立计算函数（均有单元测试，不嵌套）：

1. 整理问题文字，识别问题类型、线路、段数、包装、是否问邮寄、是否需转人工、条码。
2. 用条码、叫法、英文词和中文词给商品打分，按客人说的段数排除其他段。
3. 判断按邮寄奶粉还是店内商品回答；需要时追问段数或请客人确认商品。
4. 查事实：店内库存、批次日期、零售价、近 14 天最低售价；或邮寄奶粉同款各线路设置和价格。
5. 生成给客人的回复和客服参考，附上匹配的固定回复。
6. 写回复记录。

### 6.6 前端

- 问答栏：回复下显示"需人工确认"标记（如有）、客服参考，以及"复制回复、修改后采用、重新生成、转人工"；复制即记为采用，修改后保存即复制并记为修改后采用。
- 管理员在问答栏右上角"设置"里维护邮寄奶粉、客人叫法、固定回复；页面处理加载、空数据、失败、无权限四种状态。

阶段 2 不使用外部大模型。阶段 3 再评估接入大模型做问题理解和语气润色，价格、库存、日期仍只取系统，并由代码逐项核对。
