## 1. 需求来源

| 日期 | 渠道 | 内容摘要 |
| --- | --- | --- |
| 2026-10-24 | 客户反馈 | 按 10-24 重新点货清单在手机上逐个核对商品：可调整数量与到期日，无误可直接确认；每确认一个商品即写入库存系统并从待办中减少一个，直至全部完成 |

## 2. 目标

1. 甲方在手机上按清单逐个盘点，确认即生效，不再经过 Excel 回填与二次录入。
2. 每次确认都有库存流水与审计记录，可追溯、可再次修正。
3. 盘点期间 POS 正常营业，销量不重复扣减、不遗漏。

## 3. 范围

### 3.1 包含

- 库存系统（手机端）新增“盘点任务”页面：进度、清单、逐项核对、确认。
- 盘点清单：10-24 核查得出的 663 种商品（高 127、中 501、低 35）导入系统；支持扫码把清单外商品临时加入。
- 确认后按“实物批次”对齐库存，生成盘点流水与审计。
- 盘点确认时间之前的 POS 销量不再对该商品扣减。

### 3.2 不包含

- 经营管理端的盘点入口。
- 仓位（系统尚未建立仓位）。
- 多人同时分工盘点的任务分配（同一商品被两人同时确认时，后确认者会被提示刷新）。

## 4. 业务规则

| 编号 | 规则 |
| --- | --- |
| R1 | 每个商品显示系统当前各批次（到期日、数量）作为初始值；甲方按实物修改数量、修改到期日、新增或删除批次 |
| R2 | 确认时按到期日对齐：实物有、系统有 → 调整到实物数量；系统有、实物没有 → 调整为 0；实物有、系统没有 → 新建该到期日批次并增加。一次确认在同一事务内完成 |
| R3 | 实物与系统完全一致时也可确认，记为“已核对，无差异”，不产生库存流水，只留审计 |
| R4 | 确认后该商品从待办中移除，进度减一；已确认商品可在“已完成”中查看，需要时可再次盘点（再次按 R2 对齐） |
| R5 | 确认时若该商品库存在打开后发生变化（例如 POS 刚扣减），提示刷新后重新确认，不覆盖 |
| R6 | 该商品确认时间之前下单的 POS 销量不再扣减（实物已经点过）；之后的销量照常扣减。规则与 2026-10-20 基准重建一致 |
| R7 | 流水类型为盘点增加 / 盘点减少，来源标记为本次盘点任务；每次确认写一条审计，记录调整前后的批次明细 |
| R8 | 仅具备盘点权限的账号可操作 |

## 6. 技术方案（摘要）

| 层 | 内容 |
| --- | --- |
| 数据库 | 新增盘点任务与任务明细两张表（版本化迁移，含回滚说明）：任务（编号、门店、仓库、状态、创建人、时间），明细（商品、优先级、列入原因、状态、确认前后数量、确认人与时间） |
| 导入 | 导入脚本读取 10-24 清单，预演后 `--execute` 写入；执行前备份 |
| 接口 | 查询任务与明细；确认某商品（提交实物批次列表与幂等键）；扫码加入清单外商品。复用现有盘点的版本校验、权限与审计写法 |
| POS 扣库 | 扣库时若商品在订单时间之后已完成盘点确认，则该明细不扣减，标记为“盘点已覆盖” |
| 前端 | 新增独立组件（不再扩大 `App.vue`），工作台增加“盘点任务”入口 |

## 7. 验收标准

| 编号 | 验收内容 |
| --- | --- |
| A1 | 手机（375–430 宽）上可完成：筛选、搜索/扫码、打开商品、修改数量与到期日、新增/删除批次、确认 |
| A2 | 确认后数据库余额 = 实物批次；流水净额 = 余额；审计记录调整前后明细 |
| A3 | 确认后进度减一；“已完成”中可查看并可再次盘点 |
| A4 | 并发：确认前库存变化时提示刷新，不覆盖 |
| A5 | POS：确认时间之前的订单不扣该商品，之后的订单正常扣 |
| A6 | 自动测试覆盖对齐规则、并发、POS 覆盖规则与权限；现有测试全部通过 |

## 8. 影响评估

| 方面 | 影响 |
| --- | --- |
| 数据库 | 新增两张表；不修改现有表结构 |
| 库存 | 每次确认写入正式库存（盘点流水） |
| POS 扣库 | 增加“盘点已覆盖”判断，仅影响已盘点商品在确认时间之前的订单 |
| 风险 | 中：写入正式数据。上线前备份；先在演练库验证导入与确认 |

## 9. 实施与上线

1. 本说明书确认后开发（预计 1 个工作单元），提交前在演练库完成导入与确认验证。
2. 甲方确认提交后合并上线：备份 → 执行迁移 → 导入清单 → 甲方开始盘点。
3. 回滚：停用入口；已确认商品可通过再次盘点修正；迁移可回滚删除两张新表（不影响库存流水）。
